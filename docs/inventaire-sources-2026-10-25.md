# Inventaire technique des sources de veille — écosystème santé numérique (Québec)

Sondage réalisé le 2026-10-25 en ligne de commande (`curl -sL -m 20`, User-Agent par défaut de curl, aucune usurpation, aucun contournement). Tout ce qui a été téléchargé est dans `dl_sources/` (données non fiables), les scripts dans `scripts/` (`probe.sh`, `summarize.sh`, `analyse_feeds.py`, `feeds.txt`).

Méthode par source : (1) emplacements standard `/feed/`, `/feed/atom/`, `/rss`, `/rss.xml`, `/feed.xml`, `/atom.xml`, `/?feed=rss2` + balises `<link rel="alternate">` ; (2) WordPress `/wp-json/` (espaces de noms), `/wp-json/wp/v2/posts`, The Events Calendar (`/events/?ical=1`, `/evenements/?ical=1`, `/wp-json/tribe/events/v1/events`, `/events/feed/`) ; (3) autres CMS ; (4) iCal ; (5) sinon HTML (balises `<time datetime>`, dates visibles, JSON-LD `Event`).

Légende fiabilité : **A** flux structuré avec dates d'événement · **B** flux RSS/Atom de nouvelles (date de publication seulement) · **C** HTML structuré (balises `<time>`, attributs data-*, JSON-LD) · **D** HTML peu structuré · **X** bloqué / rien.

Remarque sur « Dernier élément » : pour les flux RSS, c'est la date `pubDate` de l'élément le plus récent ; pour iCal / REST TEC, c'est la date d'événement la plus éloignée dans le futur (et la plus proche en précisant).

## 2. Constats transversaux

**CMS et formats**
- Sur ~65 sites sondés, **~34 sont WordPress** (détecté par `/wp-json/` ou `wp-content`). Tous exposent au moins `/feed/` (RSS 2.0) et `/feed/atom/`. Le flux général est donc le dénominateur commun — mais il ne contient que des dates de publication.
- **The Events Calendar (TEC)** est présent sur 7 sites WordPress : RSN, RQRV, Digital Health Canada, RIISQ, Génome Québec, Hacking Health, (trace sur Obvia non confirmée). Seuls **3 ont des événements** (RSN, RQRV, DHC). Sur ces sites, trois accès structurés fonctionnent : `?ical=1` (iCal), `/wp-json/tribe/events/v1/events` (JSON avec `start_date`/`end_date`/`url`/`venue`) et `/events/feed/` ou `/evenements/feed/` (RSS dont le `pubDate` = date de **début d'événement**, utile à savoir). Le slug varie selon la langue : `/events/` et `/evenements/` fonctionnent souvent tous les deux (WPML).

## Incertitudes
- Les sites bloqués (RI-MUHC, CHU de Québec, McGill, Polytechnique, Zeffy, santequebec.ca) peuvent très bien exposer des flux à un navigateur ; ils n'ont pas été testés autrement qu'en ligne de commande.
- Les sites rendus en JavaScript (Acfas calendrier, UdeM calendrier, Inforoute, Montréal InVivo événements, CRM activités) peuvent contenir des données structurées non visibles dans le HTML statique.
- Les 000 (connexion refusée/timeout) sur qprn.ca et research.chusj.org sont peut-être dus au parallélisme du sondage ; à revérifier séquentiellement.
- Les sites de RARE.Qc, ODISÉ, PR3CRISA, AIRS, ThéCell, IRSPUM, SD4H n'ont pas été identifiés ; la recherche web n'a pas renvoyé d'URL officielle.
