# Plan d'implémentation — rsn-veille 0.3.0, la page après son premier passage sur rsn.quebec

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE : superpowers:subagent-driven-development (recommandé) ou
> superpowers:executing-plans, tâche par tâche. Les étapes sont des cases à cocher (`- [ ]`).

**But :** livrer les six retouches validées sur la maquette v9 : bandeau continu avec l'en-tête du thème, « À la une »
de la même couleur, flèches des dates limites, fiches RSN sur fond gris très pâle avec trait jaune, pastille « Appel »
en contour, appels sans date limite et séries en cours placés à la date du jour.

**Architecture :** un filtre `body_class` dans `Raccourci` marque la page qui affiche le raccourci ; `veille.css`
reçoit une section d'adaptation au thème Vault (préfixée `body.rsn-veille-page`, inerte ailleurs) et les nouveaux
styles ; le gabarit PHP change l'ordre de ses blocs et remplace `.actions` par `.bandeau` ; `veille.js` enveloppe le
corps des fiches dans `.corps`, place les appels sans date limite et les séries en cours à la date du jour, et pilote
les flèches. La constante des appels sans date limite passe de 90 à 30 jours. Aucun changement d'API, de données ni
d'administration.

**Pile :** PHP ≥ 8.0, WordPress (bouchons `tests/bouchons-wordpress.php` pour PHPUnit 9), CSS, JavaScript sans
dépendance. Vérification : `vendor/bin/phpunit`, `php -l`, `node --check assets/veille.js`.

**Conception :** `docs/superpowers/specs/2026-10-27-page-0.3-design.md` (le résultat visé est
`docs/maquette/gabarit-v9.html` : la lire pour les valeurs CSS et le rendu attendu).

## Contraintes globales

- Tout en français : code, commentaires, commits, documents. Commits au seul nom de Tess (jamais de `Co-Authored-By`
  ni de mention d'un assistant).
- Préfixes `rsn_veille_` / namespace `RSN\Veille` ; textes publics via `__()` domaine `rsn-veille` ; CSS préfixé
  `.rsn-veille` (sauf la section d'adaptation au thème, préfixée `body.rsn-veille-page`) ; `@media (max-width:820px)`
  dupliqué dans `@container rsn-veille (max-width:760px)` comme en 0.2.0.
- Ne pas cacher ni remplacer l'en-tête du thème ; ne rien changer au JSON public, à l'iCal, à l'administration, à la
  collecte, au formulaire.
- Le script public n'a pas de banc d'essai : `node --check` obligatoire ; chaque tâche JS fait aussi tourner le
  script contre un faux DOM minimal (voir Tâche 5) pour s'assurer qu'il s'exécute sans exception.
- `vendor/bin/phpunit` vert à la fin de chaque tâche (534 tests au départ).

## Points de vigilance

1. **Section `agenda` sans bande des dates limites** : `#lim-prec`, `#lim-suiv` et `#limites` absents ; `majFleches`
   et les écouteurs doivent se taire. Test : Tâche 5, exécution du script sur un DOM sans ces nœuds.
2. **Appel sans date limite publié dans le futur** (préannonce datée) : `cleTri` = `debut`, pas `AUJ`. Test :
   Tâche 5, vérification manuelle dans le faux DOM.
3. **Événement d'un jour commencé hier sans `fin`** : passé, pas « en cours » (`enCours` exige `fin`). Test :
   Tâche 5.
4. **Mobile** : les anciennes règles mettaient `.im` et `.tx` en `grid-column:2` ; avec `.corps` à une colonne, elles
   créeraient une colonne fantôme. Toutes les occurrences (820 px, conteneur 760 px, 640 px) sont remplacées.
   Vérification : Tâche 4, `grep -n "grid-column:2" assets/veille.css` vide.
5. **Page d'archive ou flux** : `body_class` ne doit rien ajouter hors `is_singular()`. Test : Tâche 2.
